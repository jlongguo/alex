# 安全与隐私边界（必须在硬件阶段落实）

## 当前实现只用于模拟

- 软件中设置 `emergencyStopped=true` 仅锁定模拟运动；不具备硬件刹车、碰撞认证、机械失效检测。
- 软件中的动态障碍是静态几何点，不代表视觉或 LiDAR 能识别儿童、台阶、宠物或透明物体。
- 软件内角色切换仅供权限测试；家长身份还未验证，任何本机使用者都可以伪装家长。
- 不允许接入实际电机、智能门锁、摄像头持续采集等有安全/隐私后果的设备。
- 服务仅监听 127.0.0.1。不得将端口转发至互联网。

## 接入实体机器人前的门槛

- 独立安全 MCU / 电机禁用线路、实体急停、失联自动停、低速测试、碰撞/悬崖检测和防夹伤设计。
- 导航任务签名或双向设备认证，明确的授权和目标区域限制。
- 本地运动监控的优先级必须高于中枢/云端 Agent；远程命令不可覆盖本地安全停止。
- 儿童相关摄像头、音频、身份与学习数据按最小必要原则处理；家长授权、查看、删除与物理隐私开关。
- 家庭用非载人机器人，应在有人监管的平坦封闭场地测试，不应被当作儿童看护设备。

## 真实 Agent 接入前

所有调用经过 schema 校验 + PolicyEngine + 明确的设备能力匹配；有风险的操作二次确认。防止工具调用注入、越权跨设备访问、任意 Skill 读取家庭数据。

## v0.12 ROS simulation-only acceptance

- `ALEX_ROS_SIMULATION_ONLY=1` and `ALEX_RUN_ROS_INTEGRATION=1` are both required before launching the three-leg acceptance harness.
- Domain `77` with `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` is intended to reduce accidental discovery of other ROS networks; **it is not certified isolation**. Do not run any physical robot on the same host/domain.
- Live navigation acceptance requires a *fresh* independently observed TF pose, Nav2 action success and feedback. A passing offline/CI test suite is never a substitute.
- A ROS Nav2 cancellation or process-group termination is not a physical emergency stop, and none of these scripts are approved for real motors.

## R3 独立学习者与虚拟终端

学习者 PIN 只允许经验证的本地家长设置。凭据以带随机盐的 scrypt 摘要保存在私有文件；录入后的明文 PIN 不会在 API/审计中返回。孩子登录的 learnerId 是服务器绑定的，不信任浏览器提交的 profileId。

本地会话原文若开启持久化仍是明文 JSON，因此不应开放公网、共享磁盘或进行云端公开部署。原共享儿童 PIN 是兼容身份，不保证按每个真实孩子隔离；需要由家长逐个设置独立登录身份。家长删除档案时同时撤销登录并清理本地相关对话数据，但远端模型日志与备份不在清理范围。

Virtual Device 协议 v3 的 display.face / audio.output 渲染反馈只说明 **模拟进程自报已输出表情或字幕**，不是实体显示/发声证明。不能把软件会话取消、语音按钮或模拟紧急停止直接当成硬件安全能力。

## R4 课程成果限制与隐私

文字课程仅验证事先编写的有限句型/选项答案。“完成”只说明指定的本地文字步骤被执行，不代表语音能力、学习成效、科学知识水平或安全行为达标。模型生成的赞扬不允许形成正式成果事件。不同孩子使用服务端确认的身份，课程目标由家长设置。学习成果和会话必须遵循删除/导出；自动滚动淘汰会话可以保留有界成果，最多每个身份 128 项，之后会淘汰旧事件。

本地家长课程计划是独立的 JSON 文件；聊天/成果只在显式开启 ALEX_CONVERSATION_PERSIST 时落盘，文件仍为明文。多个文件上的更新缺乏真正的多文档事务保护，公网部署或云端处理儿童信息需要后续数据库、加密、迁移、保留期、家长同意及供应商隐私评估。不要把低延迟全双工 ASR/TTS、真正的语言评分、自动执行设备或硬件安全能力视为已经实现。

## R5 云端模型授权、浏览器语音和跨孩子隔离

每个孩子的语音识别、语音朗读和第三方文字模型默认全部关闭。只有在本地家长明确为对应独立学习者授权后，服务器才接受向家长配置的模型发送该孩子的文字及近期聊天。只用受限枚举的语言、节奏、兴趣构造个性化上下文，禁止任意脚本或家长全部记忆传给模型；服务端每回合核对云端授权，撤销时尝试中止当前模型请求。不能保证第三方已经收到的文本会被删除。

语音功能由真实浏览器 Web Speech 接口处理，并非全离线本地 ASR。浏览器厂商可能处理麦克风音频；即使家长在 Alex 中授权，孩子仍需点击按钮并处理浏览器权限。应用只接收可见文字、需用户再次点击发送，不能自动唤醒、自动传送语音或自动调用设备。页面检查授权失败则禁用语音；浏览器断网、休眠可能延迟撤销生效，物理麦克风隐私开关和真实数据合规仍需单独设计。
 
## R6 独立的第三方音频处理风险

本地 `MediaRecorder` 短录音只有用户主动点击并通过家长两层音频授权，才会发送给家长在服务端配置的 HTTPS ASR 供应商。云端朗读只在用户点击后把回复文字发送给 TTS 服务商。Alex 的浏览器与服务端不主动持久化原始音频；这**不限制第三方供应商、浏览器或中间网络组件自身的数据处理**。

短录音有 1.5 MB 传输上限和浏览器最长约 15 秒的操作约束，但目前仅通过一个可伪造的客户端时长头声称录音长度，**服务端没有解码校验实际声学时长或恶意媒体内容**，不应上公网、更不应将此视为儿童真实生产合规。后续必须实现可信媒体解码/时长检测、供应商最小留存政策评估、用户删除请求和严格日预算成本限制、加密存储/日志隐私审计、并持续遵守硬件和真实麦克风安全要求。

## R7 增量录音与静音停录限制

R7 浏览器短录音在用户点击后可增量传入 Alex。增量分片在录音**尚未结束前**可能已经上传，家长启用的是第三方录音传输许可，且界面会明确提示；上传到供应商仍由服务器在 finish 后进行。音频只在内存中临时拼接，严格身份隔离、序号、数量与超时限制；没有文件写入。浏览器静音检测为 RMS/噪声底启发式算法，可能误把音乐/风噪判断成人声，或把低声说话当作静音，绝不可用作儿童健康、语言能力、声纹或行为评估。

真正上公网前，必须补音频内容的可信解码、实际媒体时长限制、反恶意媒体处理、开销预算、真正的供应商儿童政策与供应商删除/日志治理。不能把模拟 Provider 的低延迟、CI 测试或页面指标当成真实音质和生产实时语音证明。

## R8 真实上游实时转写的附加隐私风险

R8 在用户主动点击之后，浏览器 AudioWorklet 将麦克风 PCM16 帧经本地 HTTP 发送给 Alex，再由服务器**在说话的同时**将样本传给第三方 WSS ASR。这与 R7 “录制完才发给供应商”有实质区别。家长现有 cloudAudioInputAllowed 与 voiceInputAllowed 仍须双重启用，服务端逐帧、每次启动和最终提交都会校验，且身份切换/后台化会停止当前录音。已发给供应商的内容不可通过浏览器后续取消撤回。浏览器端重采样是基础实现，没有生产级抗混叠/采样率真实性证明，不能把它作为声纹、说话人认证、发音测评或儿童语言评估。没有自动唤醒、持续录音、机器人控制或自动消息发送。

必须额外验证真实服务商的未成年人语音政策、音频处理区域、费用上限、删除支持、真实噪声/口音识别率、真实 P50/P95/P99 延迟以及第三方日志。测试专用 WSS fixture 不会产生真实供应商安全/质量认证；默认不启用此功能。不应直接开放本地 HTTP 到公网。

## R9 流式朗读与用户主动打断的儿童安全界限

第三方 PCM TTS 只有在用户主动点击且父母独立开启 `voiceOutputAllowed` 与 `cloudAudioOutputAllowed` 后才会接收选定回复文字。Alex 本地环回接口持续验证身份和归属，限制音频总量、同一孩子并发、请求频率及未确认缓冲；用户通过“打断”明确停止声音并可继续语音输入。已发给供应商的文字及其生成音频无法通过本地取消撤销。浏览器 WebAudio 播放回调只是客户端声称已播完，**不能证明儿童听到了，不能推导儿童学习表现或语言理解结果**，不得据此形成自动评分。

R9 并非真正全双工 AI 自然对话，不支持常驻麦克风与自动唤醒，不能把 streaming TTS 作为语音控制机器人、开锁或操作实际硬件的授权通道。默认关闭，上公网、实际儿童使用和商业化前必须核实供应商政策/费用/留存和实时音频质量及设备音量安全。
