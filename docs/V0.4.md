# Alex v0.4 — Device Identity, Pairing, Profiles, Privacy & Memory Context

## Status
- Home hub and robot are still **software simulation only**. No real motion safety guarantees.
- Require `AUTH_MODE=local` for pairing. All HTTP interfaces bind to loopback.
- Default agent is deterministic. Hosted model access is optional.

## Device pairing
1. Parent logs in via `/api/auth/login`.
2. `POST /api/devices/pair/start` with `{}` yields one-time 24-hex pairing code (5 minutes). Creating a newer code invalidates older codes.
3. A local device emulator calls `POST /api/devices/pair/complete` with `{code,name}` while code is valid, receiving `deviceId` and a 64-character hex token **once**.
4. `POST /api/devices/heartbeat` with `{deviceId}` and `Authorization: Bearer <token>` updates last-seen time. Revoked credentials fail.
5. Parent revokes with `POST /api/devices/revoke` `{deviceId}`.

Tokens are generated randomly; only SHA-256 hashes are persisted in `.local/devices.json` (private local file). Pairing cannot move robots or access family data. The local server does not yet have a transport-secured LAN onboarding workflow, and must NOT be exposed outside loopback.

## Profiles
Parent can add learner profiles with `POST /api/profiles` `{nickname,ageBand,interests}` and delete with `POST /api/profiles/delete` `{id}`. `GET /api/profiles` returns nicknames, age bands, interests. No exact DOB, voiceprint, or location is stored. **All profiles still share a single `child` login role**; do not treat them as isolated multi-child accounts. Profile-specific memory must wait until verified per-profile login.

## Privacy
- Parent `GET /api/privacy/export` exports learner profile metadata and family memory, never device tokens or passwords.
- Parent `POST /api/privacy/erase` `{scope:'child'|'family'|'parent'|'all'}` deletes the specified memory scope persistently. It does NOT erase profiles, audit metadata, backups, or hosted provider logs.
- Parent can delete individual profiles and revoke individual paired devices separately.
- No voice recordings or raw chat transcripts are stored by these modules.
- Existing `.local` files remain plaintext at rest; protect your operating-system account and backups.

## Agent memory (opt-in only)
`AGENT_MEMORY_CONTEXT=1` enables sending up to 8 role-filtered short memory hints (max 200 characters each) to the configured hosted LLM. Default is off. Child sessions never receive `parent` scope notes. Hints are untrusted data, not executable instructions; policy checks remain authoritative. Read your LLM provider's data terms before enabling with family data.
