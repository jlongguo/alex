# Alex / Home Agent OS v0.2 — engineering notes

## Implemented

- `AgentProvider`: deterministic `RuleAgentProvider` by default; opt-in `CompatibleAgentProvider` for HTTPS OpenAI-compatible chat-completions. Model proposals are validated as structured intent before any dispatch. No shell or generic tool execution.
- `SkillRegistry`: trusted, in-process skill manifests with ID/version, enablement, role rules and required capabilities; unsupported hardware capabilities are denied. Built-in English/story skills remain demonstrations, not real education services.
- Navigation task identifiers (`requestId`) support bounded-history idempotency. Identical retries return the same task; changed destinations on the same key fail. Timeout stops the simulated robot.
- Local JSON snapshot writes with serialized atomic rename. Every mutating HTTP request awaits a snapshot before success is returned. Tasks/events survive process restarts. Running tasks are **stopped** after restart; motion never auto-resumes, and the simulated robot returns to the default dock position.
- Real model access is opt-in through environment variables, disabled by default. Its external service was not live-verified; tests use a mock-compatible API response.

## Security and scope limits

**Simulation only.** Local HTTP still has no real authentication, and the `actor` request field is an untrusted test role. No live motors, cloud-connected home devices, cameras, recording, child account storage or physical safety implementation. Never expose the HTTP port to the Internet or bridge commands to physical actuators.

No third-party JavaScript plugin sandbox. Only trusted source-controlled skill plugins can be registered. A child skill must satisfy both the manifest's `allowedActors` and `PolicyEngine`'s allowlist; model output cannot change either. Future work: first-class parent auth, consent, device pairing, stronger isolation for external skills, database transactions and audited actions.

## Environment variables

| Name | Default | Meaning |
|---|---|---|
| `PORT` | `4317` | Local port |
| `HOST` | `127.0.0.1` | Keep loopback only |
| `STATE_FILE` | `.local/state.json` | Snapshot path (sensitive, local) |
| `AGENT_PROVIDER` | `rules` | `rules` or `compatible` |
| `AGENT_BASE_URL` | unset | Trusted HTTPS chat-completions base URL ending at `/v1` |
| `AGENT_MODEL` | unset | Provider model ID |
| `AGENT_API_KEY` | unset | Secret credential, never commit |

Run from project root: `npm install && npm test && npm start`. For the opt-in provider, set environment variables at process launch; no AI keys are placed in the web browser.

## HTTP changes

- `GET /api/health` now includes `agentProvider` and `persistentTasks`.
- `POST /api/tasks` optionally accepts `requestId` (8–100 URL-safe chars) and `timeoutSeconds` (1–600).
- `POST /api/command` optionally accepts `requestId` for navigation deduplication.
- Returned task includes timing metadata and optional request ID.
- `requestId` only deduplicates among the last 100 retained navigation tasks; it is not a forever-replay cache.

## Tests and acceptance

`npm test` runs unit, module, and HTTP integration tests. Restart recovery is tested using a real temporary filesystem and two independent Node server processes. LLM authorization is tested using a mock provider and invalid tool proposals. Tests do not prove real cloud provider compatibility, robot functional safety, or browser E2E interactions.
