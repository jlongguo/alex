# Alex v0.14 — ROS runtime acceptance reliability

**Status: code and offline tests completed; real Gazebo/Nav2 three-leg navigation remains unverified.** Do not connect to physical motors or treat Nav2 cancellation as an emergency stop.

## Blocking bug: colcon overlay in a child process

The old `scripts/launch-ros-sim.sh` compiled `alex_sim` and sourced its overlay only in the launch child. `scripts/run-ros-acceptance.sh` ran `ros_smoke.py` from the parent. Environment changes from a child **never propagate back to its parent**; the acceptance could therefore fail with `ModuleNotFoundError: No module named 'alex_sim'` despite Gazebo running.

`scripts/prepare-ros-sim.sh` must be **sourced** by the invoking shell. It verifies ROS 2 Jazzy, `ALEX_ROS_SIMULATION_ONLY=1`, isolated ROS domain 77, required ROS packages, locally generated Nav2 params and the exact local `alex_sim` overlay. It builds once, then the launch child verifies and reuses that overlay instead of rebuilding. The acceptance parent now imports `alex_sim` through the same sourced environment.

## Current-run evidence binding and diagnostics

Every acceptance attempt clears old success state, creates a fresh run ID, and passes it through `ALEX_ROS_ACCEPTANCE_RUN_ID` to the live ROS smoke test. After all three navigation legs, `verify-ros-report.py --run-id` rejects reports from another invocation. Run IDs protect against accidental stale reuse, **not** deliberate host tampering.

Every invocation writes `.local/ros/diagnostics.json` (configurable via `ALEX_ROS_DIAGNOSTICS`) with bounded log hints and preflight blockers. The manual `.github/workflows/ros-sim-acceptance.yml` uploads this file with the acceptance report, launch log and preflight data. Diagnostics are informational, never proof of Nav2 or Gazebo success.


The current development machine lacks ROS 2/Gazebo, so `sim:preflight` correctly reports `blocked`. `node --test tests/v14.test.mjs` runs explicit fake-overlay parent/child tests, wrong-domain and foreign-overlay rejection, report ID mismatch and blocked-run diagnostic checks.

## Real acceptance on dedicated Ubuntu 24.04 hardware-free simulation host

```bash
source /opt/ros/jazzy/setup.bash
export ALEX_ROS_SIMULATION_ONLY=1
export ALEX_RUN_ROS_INTEGRATION=1
export ALEX_GZ_HEADLESS_RENDERING=1
export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
npm run sim:accept
```

Review `.local/ros/acceptance-report.json`, `.local/ros/diagnostics.json`, `.local/ros/preflight.json` and `.local/ros/acceptance-launch.log`. Only a real `passed` report with all three goals, Nav2 Action feedback, fresh map TF, actual odometry movement and a matching run ID can establish ROS simulation acceptance.
