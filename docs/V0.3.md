# v0.3 — Local family authentication, audit and scoped memory

## Scope

**This is a local-only simulation.** It is not a hardened Internet-hosted service, a physical robot safety system, nor a production child-data compliance implementation. Do not port-forward the HTTP server or connect its commands to motors.

### Authentication modes

- `AUTH_MODE=demo` (default for backward compatibility): **insecure** demonstration. Role in client requests is untrusted and selectable. Bind to loopback only.
- `AUTH_MODE=local`: requires `ALEX_PARENT_PASSWORD` (12+ characters) and optionally `ALEX_CHILD_PIN` (6–12 digits). Login creates an unpredictable 8-hour, process-local, HttpOnly, SameSite=Strict cookie session. Server ignores any role supplied in API bodies; it uses the authenticated actor.
- Failed logins are rate-limited per client IP (five failures -> five-minute lockout). Password/PIN comparisons use scrypt-based derived values and constant-time compare. Secrets come from environment variables, are not persisted and are never returned by API.
- Restart invalidates sessions. Browser UI provides login and logout. Demo role selector is disabled in local mode.
- Strict Host and Origin checks prevent accidental cross-origin and DNS-rebinding use, and startup is refused for non-loopback binding. There is **no HTTPS listener** or remote access support.

### Persistent family memory

- `GET /api/memory`: parent sees all entries; child sees only `family` and `child` scopes.
- `POST /api/memory`: parent may add text memories up to 1,000 characters; 200 entries max.
- `POST /api/memory/delete`: parent may remove by entry UUID.
- Stored in `.local/memory.json` using sequential atomic writes. Family data is not sent to the LLM yet, and there is no automated extraction or memory dreaming.
- This is a manual record system for early prototyping, not yet a semantic long-term memory engine. Do not store sensitive child recordings or personal identifiers.

### Audit

- Append-only newline-delimited JSON file `.local/audit.jsonl`: timestamp, verified actor, action name, outcome, optional requestId.
- Raw prompts, passwords, PINs, recordings and memory text are **not included** in audit events.
- Parent-only `GET /api/audit`. A plain JSONL log is not tamper-resistant or a remotely replicated compliance audit log.
- Audit and task/memory state are separate local files; no cross-file transaction is guaranteed.

### Important next steps

1. Device credentials and local device pairing (no hardcoded manufacturer secrets).
2. Explicit child profile IDs, consent, retention/deletion controls and encrypted storage.
3. Make real Skill access use verified session context; keep child/parent permissions separate.
4. Harden session/CSRF model for any future cross-device HTTPS deployment.
5. Extend integration/Playwright tests for browser login and multi-session behavior.

## Quick start

```bash
npm install
npm test
AUTH_MODE=local ALEX_PARENT_PASSWORD='replace-with-a-strong-unique-passphrase' ALEX_CHILD_PIN=654321 npm start
```

Open http://127.0.0.1:4317 and log in as Parent or Child. The example PIN above is **not** secure for actual household use.
