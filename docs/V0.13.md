# Alex v0.13 — ROS Launch execution validation, headless LiDAR and trustworthy acceptance evidence

**Status: implemented and offline-tested. Real Gazebo/Nav2 three-leg acceptance remains unverified.**

This batch closes concrete v0.12 integration gaps without expanding to real hardware.

## Fixes

1. **Nav2 startup NameError:** `sim.launch.py` referenced `bringup` without defining it. The launch now resolves `nav2_bringup` via ROS package discovery and checks the actual `bringup_launch.py` file exists. A missing file is an explicit error.
2. **ROS launch semantic test:** `scripts/validate-ros-launch.py` executes `generate_launch_description()` with stubbed ROS Launch APIs, checks the Gazebo and Nav2 include paths/arguments, and exercises missing flags, params and package failures. This catches runtime NameErrors missed by `py_compile` while honestly **not** starting ROS.
3. **GPU LiDAR headless rendering:** `ALEX_GZ_HEADLESS_RENDERING=1` enables the Gazebo `--headless-rendering` switch separately from its server-only `-s` flag. The acceptance runner enables headless rendering by default; this requires a working OGRE2/EGL or software-rendering environment. If graphics support is missing, acceptance must fail rather than pass without laser data.
4. **No stale success reports:** `run-ros-acceptance.sh` resets the previous report to `blocked` *before* checking flags/runtime. `scripts/ros-evidence.py` can only write `blocked`, `running` or `failed`, never `passed`. If launch fails, exit-handling upgrades an unfinished run to `failed`. A fresh real ROS smoke run is the only writer of `passed`.
5. **Final acceptance audit:** `scripts/verify-ros-report.py` verifies the exact three-leg sequence, independent map pose proof, all three leg entries, feedback, mileage, graph readiness, and simulation-only flag. A malformed report is downgraded to `failed` and produces a nonzero exit code.
6. **Optional live CI:** `.github/workflows/ros-sim-acceptance.yml` is `workflow_dispatch` only and needs a dedicated **simulation-only** runner with labels `self-hosted`, `linux`, `x64`, `alex-ros-sim` plus repository variable `ALEX_SIM_RUNNER_APPROVED=true`. It is intentionally never triggered by a PR or push. Configure this runner with Ubuntu 24.04, ROS 2 Jazzy, Gazebo Harmonic, Nav2, `ros_gz` and an OGRE2 headless rendering backend. Do **not** attach real robot motor controllers or place a real robot on ROS domain 77.

## Commands

**Offline development or ordinary GitHub CI:**

```bash
npm install
npm test                 # 98 automated tests in this batch
npm run sim:check        # now executes the launch description using ROS-free stubs
npm run sim:preflight    # blocked if ROS/Gazebo missing; this is expected
```

**Actual simulation acceptance — on a dedicated ROS workstation only:**

```bash
source /opt/ros/jazzy/setup.bash
export ALEX_ROS_SIMULATION_ONLY=1
export ALEX_RUN_ROS_INTEGRATION=1
export ALEX_GZ_HEADLESS_RENDERING=1
export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
npm run sim:accept
```

Results: `.local/ros/acceptance-report.json`, `.local/ros/acceptance-launch.log`, and `.local/ros/preflight.json`. Only a `passed` **route** report with three verified legs from a real ROS run can establish simulator navigation acceptance. An offline passing test or successful PR CI is **not** that evidence.

For an interactive simulation session with a desktop graphics environment, run `ALEX_GZ_HEADLESS_RENDERING=0 ALEX_ROS_SIMULATION_ONLY=1 npm run sim:launch` (it still launches the Gazebo server; a separate GUI must be started if needed).

## Remaining risks / next steps

- This environment has no ROS 2, Gazebo, Nav2, or container runtime, so **no real motion, TF, sensor, localization or physical simulation acceptance has occurred**.
- Run the manual workflow on a dedicated ROS simulation runner, inspect the first real launch logs, then fix actual middleware / QoS / TF / AMCL / lidar issues as observed.
- Do not bridge this implementation to actuators or treat Nav2 cancel as an emergency stop. Physical hardware requires an independent safety controller and field validation.
