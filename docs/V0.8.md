# Alex v0.8 — AI Proposal Gate & Family Approval

## Scope

The family hub can accept a natural-language **proposal** from the authenticated parent or child. A proposal is inert until a verified parent explicitly approves it. The proposal service maps input to **one of three existing, fixed simulation plan templates**. It does **not** let an LLM write arbitrary DAGs, invoke tools or issue motor instructions.

- `ALEX_PLAN_PROVIDER=rules` (default): local deterministic intent classifier; no cloud request.
- `ALEX_PLAN_PROVIDER=compatible`: opt-in HTTPS Chat Completions classifier. Requires `AGENT_BASE_URL`, `AGENT_API_KEY`, `AGENT_MODEL`. The natural-language prompt is shared with the configured provider. This integration is tested with a mocked HTTP implementation, not a live vendor account.
- `AUTH_MODE=local` required for all proposal endpoints. Child can only create proposals. Only a parent can list proposals, inspect the timeline, approve or reject.
- Raw user prompts, model responses, API keys and voice recordings are **not** persisted in the proposal journal. Store only template ID, actor role, approved device preference, request ID, status, timestamps and plan reference.

## API

- `POST /api/proposals/create`: `{text,requestId,deviceId?}`; child or parent; returns `pending` proposal; NEVER executes a task.
- `GET /api/proposals`: parent-only listing (no original prompt).
- `GET /api/proposals/timeline/:id`: parent-only correlated proposal and existing plan events.
- `POST /api/proposals/approve`: `{proposalId}`; verified parent only. Rechecks capabilities, permissions, availability and all plan constraints in `PlanOrchestrator.start()`.
- `POST /api/proposals/reject`: `{proposalId}`; verified parent only.

## Safety and durability

- Proposal templates are allowlisted: `learn.at.desk`, `story.at.corner`, `story.here`.
- Draft lifetime is 10 minutes. Expired/rejected/failed proposals cannot execute.
- Approval persists the `executing` state **before** invoking the plan engine; after a crash an interrupted approval is stopped, never replayed automatically.
- Request ID deduplication prevents duplicate proposals for the same actor and device. A second approval is not allowed.
- If no approved online virtual device is available, approval fails closed; the operator may submit a fresh proposal later.
- Existing physical movement and navigation are **not implemented**. Existing HTTP endpoints are loopback-only; do not expose these services on a public network.

## Verification

Run `npm test`. v0.8 adds unit and live HTTP-process tests for child/parent access, model output validation, unsafe actions, idempotency, expiry, restart and no-device failure.

## Deliberately deferred

Arbitrary model-generated plans, fine-grained child identities, real robot navigation, safety certification, SQL transactions, remotely accessible hub, real provider credentials and end-to-end cloud LLM integration.
