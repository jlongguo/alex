# Alex v0.7 — Constrained Plan Orchestrator and Event Journal

## Scope and status

Alex v0.7 adds a **deterministic, allowlisted plan executor** above the v0.5 virtual Device Gateway and the v0.2 trusted Skill Registry. It does not add an unrestricted model planner, ROS navigation, live English lessons, or physical robot motor control. It is intended for local family experimentation.

## Plan definitions and dependency graph

Three trusted templates are available:

| Template | DAG | Device capabilities |
| --- | --- | --- |
| `learn.at.desk` | `move → teach → say` | `sim.navigation.goto`, `audio.output` |
| `story.at.corner` | `move → tell → say` | `sim.navigation.goto`, `audio.output` |
| `story.here` | `tell → say` | `audio.output` |

Only known skill IDs and virtual device actions may be compiled. `validatePlanGraph()` checks unique IDs, count limits, dependencies, cycles, argument allowlists, and unsupported operations. The natural-language compiler is rules-based; it returns **only a template ID**, never executable model-generated tool names.

## Execution guarantees

- Creating a plan is parent-only in `AUTH_MODE=local`; identity is derived from server-verified cookie, not a request `actor` field.
- Device selection requires pairing, recent authenticated heartbeat, explicit approved capabilities, and no conflicting v0.6 workflow or gateway job.
- Steps execute only when their dependencies succeeded. The executor rechecks device authorization and connection before each operation.
- Plan state is saved before external virtual-device dispatch; deterministic idempotency keys bind each job. No interrupted plan or gateway job is automatically replayed after restart.
- Cancel and timeout attempt to cancel all queued/running virtual-device jobs and mark remaining steps terminal.
- A bounded durable event journal captures `plan.created`, `step.started`, `step.dispatched`, `step.succeeded`, `plan.succeeded`, `plan.failed`, `plan.cancelled`, `plan.stopped`. Events carry metadata only, with monotonic sequence numbers; events and plans share one atomic JSON snapshot.
- Spoken content is transient, not written into the plan snapshot. The virtual gateway may store the bounded outgoing audio text in its own job snapshot; do not treat this as an encrypted private learning database.
- JSON snapshots are suitable only for one local Node process. They are not a transactional multiprocess database or remotely accessible service.

## API (local parent session only)

- `GET /api/plans`: list active/terminal plans and template IDs.
- `GET /api/plans/events?after=0`: ordered bounded plan events after monotonic cursor.
- `POST /api/plans/start`: `{ "templateId": "learn.at.desk", "requestId": "request_example001", "deviceId": "optional dev-uuid" }`.
- `POST /api/plans/command`: `{ "text": "去书桌陪我学英语", "requestId": "request_example002" }`.
- `POST /api/plans/cancel`: `{ "planId": "plan-uuid" }`.

The legacy `/api/workflows/*` routes remain working. An optional `PLAN_FILE` selects the local snapshot. The v0.7 control-panel section provides plan launch, status, cancellation, and event browsing. For a true free-form AI planner, a future release needs a validated proposal schema, risk policy, bounded planning budget, user approval, test fixtures, and a safe execution engine.

## Quality gate

Run `npm test`. v0.7 tests cover DAG validation, unsupported intentions, order of actions, job-result gating, capability revocation, role binding, idempotency, fail-closed restart, timeouts, cancellation, bounded events, and HTTP auth. All actions are virtual; no physical safety properties are claimed.
