# Alex R41 — 单实例写入保护与上线前数据安全边界

## 本轮交付

Alex 的多个业务状态目前存储为本地 JSON 文件；尽管单文件写入采用临时文件加原子重命名，两个服务进程仍可能读入相同旧版本，各自写出新状态，造成后写覆盖前写。

R41 在服务端加载任何状态和执行事务恢复之前，通过 `O_EXCL` 原子创建独占标记 `.alex-writer.lock`。默认位置为 `STATE_FILE` 的目录，可通过 `ALEX_SERVER_LOCK_FILE` 指定。

- 已有标记：**拒绝启动第二个服务实例**，错误 `ALEX_INSTANCE_ALREADY_RUNNING`。
- 正常 SIGTERM/SIGINT：先保存核心状态，然后对照标记内的 PID 与随机所有者标识核对归属，最后释放本实例的标记。
- 标记被替换、无法验证归属或释放失败：报错并失败关闭，不删除别人的标记。
- 意外 SIGKILL/断电残留标记：**不自动删除、不根据 PID 看似死亡就抢占**。必须先确认原进程确实退出、检查状态数据和 WAL 的一致性，再由运维人工安排隔离恢复；切勿在仍有实例运行时删除锁文件。

## 操作限制

1. 此方案防止共享**同一个锁文件**的 Alex 进程同时写本地状态。所有使用同一套 JSON 数据的实例必须配置同一个锁文件路径；若共享业务文件但锁路径不同，无法获得互斥保证。
2. 锁文件不是网络分布式锁，不支持多主部署，不提供进程存活探测与自动重选主。
3. 不是一个通用的多文件数据库事务；R37/R40 WAL 的 crash-recovery 与签名校验仍然独立。
4. 不能在网络文件系统上假设 `O_EXCL`、缓存和原子重命名一定拥有本地文件系统相同语义。
5. 当前剩余工作：进程崩溃后的安全运维恢复工具（只读验证和人工授权解锁），JSON 持久化备份与恢复演练，真实 ROS2/Gazebo 运行验收，儿童权限/隐私审计，面向目标用户的安装与交互验收。

## 测试

新增针对同一目录重复持有、篡改所有权、残留标记拒绝抢占，以及两个真实 Node 服务进程竞争同一状态目录的完整集成测试。仍需要完整执行 `npm test`、`npm run sim:check` 和 `npm run sim:preflight`；这些预检不是 Gazebo/Nav2 真实运行验收。
