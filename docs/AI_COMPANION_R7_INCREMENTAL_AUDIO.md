# Alex R7 · 有界增量音频入口、能量型 VAD 与安全会话协议

2026-11-05 · 本文对应 R7 PR #43。Alex 是可扩展家庭 AI 智能终端。英语、故事和科学等均是独立 Skill；R7 不改变 ROS2/Nav2 或实体驱动。

## R7 已实现的真实能力

R6 只有“录完短音频 → 一次性上传”。R7 增加 **浏览器录制期间持续分片上传给 Alex**：

用户点击“开始增量录音” → 浏览器请求麦克风授权 → 服务端验证当前学习者身份、云端录音权限并分配临时会话 → MediaRecorder 按 250 毫秒生成媒体数据 → 浏览器拆成最大 64 KiB 的顺序 HTTP 分片，逐个等待服务端 ACK → 用户手动停止或可选的音量检测触发结束 → Alex 在收到 finish 后将拼接后的音频交给兼容 ASR 供应商 → 文字预览 → 用户检查并点击“发送”后才进入原 AI 对话流程。

**严格边界：增量只发生在“浏览器 → Alex”链路。供应商仍是 R6 的批处理转写，不是流式上游 ASR、WebSocket/WebRTC 实时双工协议，更不是连续自主录音。** UI 使用“增量录音（实验）”名称，原 R6“一次性短录音”继续保留作为回退。

## 不改变的隐私前置条件

`AUTH_MODE=local` 且必须拥有真实登录 Cookie。仅当前经过验证的用户可操作其会话：旧共享 child 默认没有云端权限；独立孩子必须由家长显式开启 **voiceInputAllowed + cloudAudioInputAllowed** 两项配置，且服务器要启用兼容音频 Provider。权限在 start、chunk、finish 前和 Provider 调用返回后多次验证。家长撤销云端录音授权、删除学习者或执行 child/all 擦除时会尝试立即取消该孩子的未完成分片会话和上游请求。

服务端每个临时会话只属于一个经过验证的 principal，不接受客户端伪造 profileId 或共享的跨身份 turnId。查询状态、上传片段、取消和结束都校验相同的身份归属。音频缓冲仅保存在内存中，完成、取消和过期时覆盖临时 Buffer 内容并释放引用；无文件写入、原始音频日志、长期对话记忆或学习成绩写入。云端供应商可能独立保留已接收的音频，**本地清除不能删除已经发送给供应商的数据**。

## 新增 HTTP 协议

| 端点 | 输入 / 输出 | 安全边界 |
|---|---|---|
| POST /api/audio/turn/start | JSON `{mime,language:'zh'|'en'}` → `{turn:{id,maxChunkBytes,maxAudioBytes,maxDurationMs,maxChunks,...}}` | 验证身份与音频授权后才能创建；同一身份最多一个活跃会话 |
| POST /api/audio/turn/chunk | 二进制 body；头 `X-Alex-Turn-Id`、`X-Alex-Chunk-Seq`、`Content-Type` → `nextSeq,totalBytes` | 每次都校验身份、媒体类型、连续序号与真实读取字节数 |
| GET /api/audio/turn/status?id=... | 查询自己的临时会话状态、已收到字节及序号 | 不能查询别的学习者 |
| POST /api/audio/turn/finish | JSON `{id}` → `{text,requiresManualSubmit:true,metrics}` | 服务端判断录音会话耗时，再经 ASR 得到预览；无自动聊天或设备动作 |
| POST /api/audio/turn/cancel | JSON `{id}` → `{cancelled}` | 只取消本人会话，尝试终止其上游 |
| GET /api/audio/turn/metrics | 仅当前身份的非内容指标 | 总字节数、片段数、耗时与计数，没有音频和转写文本 |

R6 旧的 `POST /api/audio/transcribe`、`POST /api/audio/speak`、`POST /api/audio/cancel` 保持兼容。

### 资源与过期约束

- **64 KiB**：单分片最多；一段音频最多 **1.5 MB**、**64 个分片**。
- **8**：同一 Alex 进程最多同时存在八个增量接收会话。
- **6 次/分钟/身份**：打开会话的速率限制；完成阶段仍经过原有 `AudioTurnGate`。
- **10 秒**：录制期长时间没有任何片段时过期；**20 秒**：绝对会话过期。
- **300–15,500 毫秒**：服务端要求从开始到结束的单调墙上时间处于限制内（15 秒 + 500ms 抖动容差）。

上述时长只能证明**服务器接收会话持续了多久**，不能证明媒体容器里的真实声学时长。恶意调用者依旧可能提交嵌入长时录音的文件。因此仍需后续可信媒体解码器验证实际帧、采样率与录音时长，才能用于公网、计费或严格风控。

## 可选能量型 VAD

`public/audio-vad.js` 使用浏览器 `AudioContext`/Analyser 分析本机 PCM 样本的 RMS。它仅保留非内容的音量/噪声底与计时指标，带有启动门槛、持续讲话判断、静音挂起和无人说话超时。用户可关闭“自动静音停录（实验）”继续手动停录；浏览器不支持 AudioContext 时也保留手动回退。

RMS 不能辨别人声、电视、宠物或环境噪声，不是经过模型训练的 VAD，不进行说话人识别、发音评分或声纹采集。安静环境可能提前终止录音，噪声大时可能无法自动结束。无人说话超时会取消临时会话而不是继续调用云端 ASR。

## 实际验收覆盖

- **可测试的服务端会话对象**：跨孩子身份隔离、分片序号、MIME、最大长度、过期、总会话上限、速率限制、取消中止、敏感数据丢弃。
- **真实 localhost HTTP**：父母/两个孩子角色、授权和撤销、另一个孩子不能读取或取消自己的会话、实际二进制分片、批量转写兼容 Provider 的输出、只有元数据的进度与审计。
- **浏览器无真实硬件测试**：MediaRecorder 录制中片段已经开始上传、按序 ACK、拆分大 Blob、停止后 finish、静音取消、切换身份时麦克风释放、无自动 chat 提交。
- **VAD 纯数值测试**：可检测持续声音与静音、忽略短暂脉冲、无声音超时、音频节点关闭和内存释放。
- **静态 UI 契约**：HTML 控件、浏览器脚本解析及 CSP 加载顺序、没有录音副作用触发机器人/设备命令。

**现场未验证的部分**：各浏览器真实的 MediaRecorder/AudioContext/权限差异、真实外部音频供应商的延迟/质量、口音和语言适应、声学 VAD 准确性、真实儿童使用后的隐私与合规；GitHub CI 无法替代这些验证。
