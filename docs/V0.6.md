# Alex v0.6 — Trusted simulated workflow orchestration

## Scope

This release adds a *deterministic* workflow orchestrator that composes existing, trusted in-process Skills with the authenticated virtual Device Gateway. It does **not** add open-ended LLM plans, real audio tutoring, physical movement, ROS integration, or a hardware safety controller.

Recipes (allowlisted only):

| Recipe | Virtual navigation | Hub skill | Device action |
|---|---|---|---|
| `study.english` | `study_desk` | `learning.english` demo | `audio.output` (text acknowledgement) |
| `story.corner` | `story_corner` | `story.interactive` demo | `audio.output` (text acknowledgement) |

Expected progression: `dispatching → navigating → speaking → succeeded`. On navigation success the hub invokes an installed, trusted skill exactly once and dispatches its bounded text to the same device. Terminal failures are **not** retried automatically.

## Security / safety rules

- All `/api/workflows/*` endpoints require `AUTH_MODE=local`; mutating endpoints require the authenticated `parent` role. Child requests cannot trigger navigation.
- Device selection requires **both** `sim.navigation.goto` and `audio.output` to be declared by the client, explicitly approved by the parent, online, and not already assigned an active workflow. If the requested device is absent or busy, fail closed rather than selecting an unauthorized replacement.
- Navigation and speech are ***virtual*** actions and simulated acknowledgements; no motor GPIO, actuator, TTS, or microphone integration exists.
- A navigation failure, cancellation, stale heartbeat or revoked capability prevents invoking the skill. Failure of the audio step prevents reporting workflow success.
- Reboot forces any unfinished workflow into `stopped`; it **never** automatically resumes. Gateway restart similarly stops pending jobs. Persistent records have capped size; raw device tokens are never persisted to the workflow file.
- All possible actions are allowlisted; arbitrary tool names or untrusted LLM plans are not accepted. Only in-process, trusted skills are allowed.
- A local emergency stop of the earlier single-robot simulator is **not** a hardware-wide emergency stop for all external virtual devices. No physical safety assurances are implied.

## API

All requests must carry a local authenticated parent session cookie.

- `GET /api/workflows` → `{workflows,recipes}`
- `POST /api/workflows/start` → `{recipe:"study.english",deviceId?:"dev-...",requestId:"unique-at-least-8"}`
- `POST /api/workflows/command` → `{text:"去书桌陪我学英语",deviceId?:"dev-...",requestId:"unique-at-least-8"}`
- `POST /api/workflows/cancel` → `{workflowId:"wf-..."}`
- `POST /api/command` also recognizes the two allowlisted composite commands before single-action classification; it requires a `requestId` and a local parent session for composites.

`requestId` is required for create operations. Repeating the same request with identical parameters returns the same workflow; conflicting parameters are rejected. The `actor` field in requests is not trusted in local-auth mode.

## Local trial

```bash
npm install
npm test
AUTH_MODE=local ALEX_PARENT_PASSWORD='set-strong-unique-password' ALEX_CHILD_PIN='123456' npm start
```

1. Log in as parent, pair a virtual device, and run the one-time virtual-device shell command shown in the console.
2. Approve **both** virtual capabilities `sim.navigation.goto` and `audio.output`.
3. In the **Workflow Orchestrator** section choose `study.english` or `story.corner`; leave the device selector blank to choose an available device automatically.
4. Observe `navigation → skill → audio` transitions, and test cancelling a task or stopping the device before arrival.

On startup the orchestrator reads `.local/workflows.json` (override with `WORKFLOW_FILE`). Logs may contain workflow IDs and step results, but do not include raw audio or tokens.

## Known limits / next milestones

- No semantic AI planning; natural language commands use a tiny deterministic phrase recognizer.
- The English and storytelling skills remain simple demo text.
- Persistent workflow file is JSON, not a transactional database; multi-process writes to the same state file are unsupported.
- Gateway uses device-SSE plus HTTP feedback; there is no durable delivery guarantee for offline clients.
- Device position, map, and audio are not physically verified, nor are device responses cryptographically attested. Treat results as untrusted simulation data.
- Next: typed plan schema, child-safe delegated permissions, more comprehensive workflow lifecycle/events, and (later) controlled ROS 2 bridges.
