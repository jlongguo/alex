# Alex R53 — 学习者浏览器会话恢复与跨儿童界面隔离

## 已核对代码的关键问题

- R46 已提供 `GET /api/learning/journey` 只读投影与历史会话选择，但浏览器没有直接“继续最近会话”入口，登录后往往只能手工找历史记录。
- 旧 `restoreCompanion()` 在 `await fetch()` 与 JSON 解析后直接修改页面，存在在途响应到达时身份已切换、仍把旧内容写到新孩子页面的风险。
- `refreshCompanionInfo()` 和 `refreshCompanionProgress()` 也有多个异步读取边界，可能将上一身份的会话元数据或学习统计绘制到当前 DOM。
- `scripts/server.mjs` 采用静态资源路径白名单，任何新浏览器脚本都必须显式注册，否则浏览器会遇到 404。

## R53 新增

1. `public/learner-resume.js`：纯客户端、无外部依赖的学习者恢复状态机。按 `learner:profile-UUID` 绑定身份，记录代际 token 与服务端返回的最多 16 个会话 ID，验证 `recentSessionId` 在拥有的集合内，切换身份和失效时清空旧授权目标。不在本地存储会话原文、PIN 或 Token。
2. 浏览器新增“继续最近会话”按钮。仅独立学习者可启用；家长及共享儿童身份不能通过该入口读取其他儿童会话。每次点击仍调用服务端原有的所有权验证接口，而不是凭客户端 ID 直接放行。
3. 历史会话恢复、课程目录、已分配计划、进度、学习旅程等异步响应返回后，校验身份代际；身份变化后忽略过期响应，避免交叉显示。权限失效或服务不可用时返回明确错误状态，不自动重试敏感请求。
4. 显式加入服务端静态资源白名单，避免新脚本 404；不扩大可访问文件集合。

## 自动化验收

- Node VM 执行真实浏览器状态机脚本，覆盖父母/共享儿童拒绝、两独立孩子身份切换、畸形/越权会话 ID、异步旧代际、同身份刷新、退出和凭据撤销后失效。
- 真正启动 Alex Node HTTP 服务，创建两个独立学习者、分配课程、完成离线英文文字会话、读回历史消息；检验另一孩子读不到会话，家长重置 PIN 后旧 Cookie 失效、新 Cookie 可以继续历史会话，退出后无法再访问。
- 真实 HTTP 静态资源与页面 GET 验证，确保浏览器恢复脚本及按钮都能实际通过本地服务器访问。
- 浏览器 HTML/JavaScript 静态结构断言，验证所有关键响应路径具备身份代际检查。

## 验收边界

以上包含真实 HTTP 进程级测试及浏览器脚本在 Node VM 中的状态测试，**尚不是 Playwright/Chromium 实际渲染与点击的跨浏览器 E2E**。项目当前 package.json 未声明 Playwright 等自动化浏览器依赖，本轮未擅自安装新依赖或更改版本。

本轮未改变 `ALEX_CONVERSATION_PERSIST` 的默认关闭策略：页面刷新只会重取服务器目前仍保留的会话；整个服务进程重启后的历史会话需要家长明确启用本地持久化。此入口不控制设备，不代表真实语音质量、ROS2/Nav2 或实体安全已验收。

## R54 优先方向

在明确浏览器环境后，为家庭向导、两个孩子切换、口语录制授权与历史会话恢复接入真实 Chromium 自动化；独立制定真实 ASR→LLM→TTS 服务和 Gazebo/Nav2 运行时的证据与阻断门槛。
