# Alex R34 — Signed Metadata Package Provenance

R34 builds a security gate around the **metadata-only** Skill package registry. This release does not execute third-party packages and does not grant new device capabilities.

## Local publisher trust

In `AUTH_MODE=local`, the verified parent enrolls a publisher Ed25519 **public** key via `POST /api/skills/trust` with `action:"enroll"`, `publisherId`, and PEM SPKI `publicKeyPem`. The parent can revoke that key with `action:"revoke"`. The private key must stay offline and must never be pasted into the Alex browser.

The publisher signs an unambiguous domain-separated payload consisting of:
`alex.skill.attestation.v1`, a newline, the canonical JSON Manifest SHA-256, a newline, and the submitted artifact bytes SHA-256.

The parent submits `action:"attest"` with `id`, `version`, `publisherId`, `artifactBase64`, and `signature`. Alex reads the **already registered** Manifest, recomputes its hash and the artifact hash, verifies the Ed25519 signature with the enrolled public key, and durably stores the digests and signature. The supplied bytes are discarded and never interpreted. Max API body remains 8KiB and thus practical artifact size is limited by request size. The included offline signer limits its input bytes to 4KiB.

For a private key generated by the publisher, use the local signing helper:

```bash
node scripts/sign-skill-artifact.mjs manifest.json artifact.bin private.pem family.publisher > attestation.json
```

Review the produced JSON, then paste it in the parent console's offline attestation form. Enroll the matching **public** key separately. Do not upload `private.pem` or expose it in browser logs.

## Mandatory server checks

Every new `review approve` and `install` operation in the HTTP server calls `SkillPackageTrust.assertTrusted` **inside the serialized registry mutation**. Missing signatures, mismatched Manifest digests, a revoked publisher and an invalid signature fail closed. Old R32 approved entries do **not** bypass this new installation gate. Existing previously installed metadata remains visible but still cannot execute; this iteration does not migrate or automatically revoke historical approvals.

The trust file is `ALEX_SKILL_TRUST_FILE`, by default `.local/skill-trust.json`. It stores public keys, verified digest records, and a locally chained event log. The event chain detects accidental or unauthenticated edits to individual records, but is **not** an external append-only ledger: someone with filesystem write access can rewrite the whole file and its chain. Treat host permissions, backups and external audit storage as future hardening.

`GET /api/skills/trust` returns only public fingerprints, recorded digests, and audit event hashes to the authenticated parent, not signatures or uploaded package bytes. State loading verifies recorded signatures against the persisted publisher public keys and rejects malformed or inconsistent snapshots. Signature verification does not establish the real-world identity or reputation of a publisher: the parent remains responsible for vetting whose public key to trust.

## No third-party execution

The package registry continues to store approved metadata only. No JS loading, sandboxed process, arbitrary device dispatch, network permission or content ingestion is enabled by a successful attestation. Package content hashes prove only that the signed **submitted bytes** match the signature. Trusted content distribution, independent publisher verification, secure rollback, atomic cross-file transactions and real ROS2/Nav2 acceptance are future phases.
