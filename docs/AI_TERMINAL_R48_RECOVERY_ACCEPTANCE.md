# Alex R48 — 离线恢复的业务启动验收与隔离副本审计

## 本轮证据链

原有 R43 备份与 R47 预检只能对文件完整性和部分环境参数做静态判断，不能证明**Alex 在恢复后可启动，且孩子的权限、课程与聊天记录仍正确**。R48 增加两级可重复验证。

### 一级：隔离副本完整性检查

在 Alex 服务已停止、备份已按 R43 创建、目标为全新空目录时：

```bash
node scripts/offline-state-backup.mjs verify /private/alex-backups/backup-new
node scripts/offline-state-backup.mjs restore-stage /private/alex-backups/backup-new /private/alex-stage-empty
npm run release:stage-audit -- /private/alex-backups/backup-new /private/alex-stage-empty
```

独立的 `scripts/recovery-stage-audit.mjs` 将隔离目标目录中的**完整文件集合**与已验证备份清单比较，检查常规文件属性、文件大小和 SHA-256，拒绝额外文件、缺文件、符号链接及损坏副本。只输出文件总数、总字节数和状态，不输出家长密码、儿童昵称或对话原文。该 CLI 不写入文件、不覆盖生产数据。

一级证据只代表 `staging-copy-verified`，**不是业务加载或恢复成功证明**。恢复副本经服务器启动后通常会产生新的状态写入，故应在启动**之前**运行该审计。

### 二级：隔离运行时 HTTP 验收

自动测试 `tests/r48-isolated-recovery-journey.test.mjs`：

1. 在测试专属临时目录中启动真实 Alex Node 服务，不连接物理设备或真实云端模型。
2. 家长创建两个独立学习者，为两人分别设置 PIN 和默认拒绝的云端隐私权限。
3. 测试环境由家长明确配置 `ALEX_CONVERSATION_PERSIST=1`，为孩子甲分配 A1 课程，登录后完成离线文字回合。该开关默认关闭，未开启时历史会话仅在内存中存在，重启后不可能恢复。
4. 正常停止源服务，核对写者锁已释放，创建 R43 备份并检查摘要。
5. 在独立的空目录还原文件，核查隔离副本与备份、源文件完全一致。
6. 针对隔离状态目录执行 R47 发布预检，并启动新的 Alex Node 服务。
7. 验证孩子甲和乙仍可分别登录、甲的历史会话和学习计划仍存在、乙不能读取甲的聊天记录。
8. 验证孩子云模型授权仍为拒绝、家长可查看隐私设置、孩子不能调用设备派发接口。
9. 正常结束隔离服务，并核对**源状态文件 SHA-256 未变化**。

另有负向测试验证备份一旦被篡改，不允许复制到隔离恢复目录并将其标为可恢复。

## 完成与不完成

- 已覆盖：模拟家庭数据的真实本机服务启动、备份、还原、重启、登录、授权、课程会话与跨儿童权限隔离。
- R48 在发布预检增加 `CONVERSATION_PERSISTENCE` 项：默认关闭时提醒无法恢复内存对话；显式开启时也只是配置检查，不代表备份/恢复验收已经完成。启用该开关意味着会将儿童文字聊天记录保存在本机，应由家长知悉并决定。
- 未覆盖：真实生产家庭数据、完整升级版本跨度、异常进程崩溃后的所有 WAL 场景、浏览器 UI、第三方云端语音质量、实体机器人、ROS2/Nav2 实时目标执行。
- **不能将上述模拟测试声称为正式环境灾难恢复已经验收**。R42 发布门槛与 R47 发布预检仍要求人工核查并保持 `releaseApproved:false`。
- 安全原则：仅对临时测试数据执行自动创建及清理。面对用户自己的备份/恢复目标，CLI 始终只读；没有自动清理写者锁或覆盖状态的回滚功能。
